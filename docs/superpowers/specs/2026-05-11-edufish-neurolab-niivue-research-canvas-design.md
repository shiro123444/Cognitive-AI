# EDUFISH NeuroLab NiiVue 研究型主画布设计

> Date: 2026-05-11
> Scope: 将 `/lab` 的主画布从手绘教学示意图升级为 `NiiVue` 驱动的轻交互研究型脑实验主视图
> Status: approved for planning

---

## 1. Goal

当前 `/lab` 已完成单屏驾驶舱重构，但主画布仍主要由前端手绘脑轮廓、绝对定位脑区按钮和自定义 pipeline 锚点组成。整体构图已经比早期卡片页更集中，但核心实验组件仍然像“定制展示层”，不够像真正的研究实验平台。

本次子项目目标不是重做整个实验台，而是替换最影响专业感的核心画布层：

1. 用成熟开源项目 `NiiVue` 承载中央脑主体，而不是继续扩展手绘脑区图。
2. 将主视图升级为“轻交互研究型”体验：支持旋转、缩放、视角复位，但不做完整医学阅片工作站。
3. 以 `3D 脑表面 + 连通性/网络视图` 作为主场景，替换当前平面脑区示意的视觉上限。
4. 科学层使用标准开源脑 `mesh / atlas / connectome` 资源，不从用户提供图片中反推拓扑。
5. 用户图片素材只参与视觉增强、教学标注和氛围层，不污染科学几何层。
6. 保留当前 `Klein Blue + 黑白灰` 视觉体系与单屏驾驶舱骨架，不推翻已完成的工作台布局。

---

## 2. Context Findings

### 2.1 当前工作台已经具备可复用的实验状态源

现有 `/lab` 页面已经提供：

1. 固定 pipeline：`source -> filter -> psd -> band-power -> ai-report`
2. 节点参数编辑：采样率、时长、通道数、滤波上下限
3. artifact 数据：
   - `signal_preview`
   - `channel_power`
   - `events`
   - `pipeline_trace`
4. AI 报告数据：
   - `node_explanations`
   - `observations`
   - `limitations`
   - `next_steps`
5. 单屏驾驶舱布局：
   - 顶部薄控制带
   - 中央主画布
   - 四角悬浮实验窗

结论：当前系统缺的不是更多数据，而是一个足够专业、足够成熟的脑实验主视图承载层。

### 2.2 当前主画布的专业感上限由自绘结构决定

当前 [NeuroLabCanvas.vue](/home/shiro/July/脑机、人工智能导论/frontend/src/components/NeuroLabCanvas.vue) 主要包含：

1. 网格背景
2. 多通道波形带
3. SVG 脑轮廓
4. 绝对定位脑区按钮
5. 绝对定位 pipeline 节点按钮

这套结构可以表达教学关系，但有三个硬边界：

1. 脑主体是示意图，不是研究组件。
2. 脑区热点和连线无法自然扩展为立体网络视图。
3. 页面再继续加样式，也容易停留在“精致前端可视化”而不是“成熟实验平台”。

结论：本次必须替换核心画布组件，而不是继续打磨手绘层。

---

## 3. User Constraints Confirmed

本轮经过逐项确认后的约束如下：

1. 本次只推进 `NiiVue` 主画布方向，不同时并入 `jsPsych / PsychoJS` 或 `BrainFlow / LSL`。
2. 主画布角色定位为：`轻交互研究型`。
3. 主体内容优先级为：`3D 脑表面 + 连通性/网络视图优先`。
4. 用户当前只能提供图片素材，不能提供结构化脑区/连线数据。
5. 科学层允许由我自行选用标准开源脑 `mesh / atlas / connectome` 资源。
6. 用户图片只作为视觉增强层，不承担科学拓扑职责。
7. 页面风格继续沿用当前 `Klein Blue + 黑白灰`，并保留不对称艺术感。
8. 首版既要保证研究平台感，也要保留视觉完成度，不能只做朴素 viewer，也不能做装饰性假 3D 脑。

---

## 4. Approaches Considered

### 4.1 Approach A: 纯 NiiVue 研究视图

将中央区域直接替换为标准 `NiiVue` 脑视图，尽量少做外部视觉层。

优点：

1. 技术路径最稳
2. 科学感最直接
3. 集成复杂度最低

缺点：

1. 视觉个性偏弱
2. 与当前驾驶舱 UI 的融合度一般
3. 用户图片素材只能非常边缘化使用

### 4.2 Approach B: NiiVue 科学层 + 前端视觉层混合

由 `NiiVue` 承载标准脑表面、热点和连通性视图，再由 Vue 层叠加实验仪器语言、边缘标注和视觉增强层。

优点：

1. 能同时建立研究平台感和完成度
2. 最大程度利用成熟开源组件，不回到完全手搓
3. 允许用户素材进入系统，但不会污染科学层
4. 与当前驾驶舱和悬浮窗结构兼容

缺点：

1. 前端集成复杂度高于纯 viewer
2. 需要严格定义层级边界，避免视觉层喧宾夺主

### 4.3 Approach C: Three.js 主场景 + NiiVue 降级为辅助层

由 Three.js 构建完整 3D 主场景，`NiiVue` 只提供部分数据或嵌套视图。

优点：

1. 视觉自由度最高
2. 艺术表达空间最大

缺点：

1. 最容易重新掉回“自己造轮子”
2. 偏离用户“优先借成熟开源项目”的方向
3. 研究平台感依赖额外大量自研细节

### 4.4 Recommendation

采用 **Approach B: NiiVue 科学层 + 前端视觉层混合**。

原因：

1. 它最符合用户“正规感”和“艺术感都要”的要求。
2. 它把成熟开源组件放在核心科学层，而不是只拿来做装饰。
3. 它可以复用当前单屏驾驶舱与悬浮窗结构，不推翻已完成的工作。

---

## 5. Design Summary

`/lab` 的主画布将从“手绘教学示意层”升级为“三层叠加的研究型实验场”：

1. `科学层`：`NiiVue` 驱动的标准脑表面、脑区热点、connectome 连线、相机交互
2. `仪器层`：波形带、pipeline 锚点、测量游标、事件标记、脑区标签、状态环
3. `视觉层`：用户图片素材提炼出的弱背景纹理、边缘注释片、教学配图和局部放大片

中央视觉重心始终是可交互 3D 脑主体。四角悬浮窗继续承担实验选择、参数检查、读数仪器和 AI 助教职责，但不再抢夺主画布的第一阅读顺序。

---

## 6. Page Architecture

### 6.1 保持单屏驾驶舱，不再改动页面骨架

`/lab` 继续保留：

1. 顶部薄控制带
2. 中央主画布
3. 四角悬浮实验窗

本次设计只替换中央主画布及其与悬浮窗的联动方式。

### 6.2 中央主画布成为绝对主角

首屏视觉顺序必须变为：

`3D 脑主体 -> 网络连线/热点 -> 波形带 -> 悬浮窗内容 -> 说明文案`

顶部 strip 和四窗都服务于中央场景，不再成为主阅读目标。

### 6.3 不对称构图规则

构图保留不对称感，但可读顺序必须稳定：

1. 中央脑主体略偏视角摆放，不做正中教具图
2. pipeline 锚点沿边缘或轨道分布，避免形成一排流程卡片
3. 边缘图片素材只在局部形成“研究注释碎片”，不做对称拼贴
4. 左下波形带视觉分量应低于脑主体，但高于一般说明文字

## 7. Main Canvas Design

### 7.1 科学层：NiiVue 研究型主视图

科学层由 `NiiVue` 承载，包含：

1. 标准开源脑表面 `mesh`
2. 标准区域集合或 `atlas` 对应的脑区分段
3. 可视化连通性网络 `connectome scaffold`
4. 脑区热点强度
5. 受控相机视角

首版交互要求：

1. 支持旋转
2. 支持缩放
3. 支持轻平移或受限视角移动
4. 支持视角复位
5. 不暴露医学阅片级图层控制面板

### 7.2 默认视角

默认相机采用偏侧上方研究视角，而不是正交教具视角。

目的：

1. 形成研究平台感
2. 保持不对称构图
3. 为边缘注释层留出空间

### 7.3 脑区热点

脑区不再通过白底按钮表现，而是通过以下方式表达：

1. 表面局部强度变化
2. 边缘光晕
3. 轻量脉冲
4. 选中态高亮

热点必须与实验数据驱动，不允许出现和当前状态无关的常亮装饰。

### 7.4 Connectome 连线

connectome 连线是主画布的重要状态层，不是装饰线稿。

状态要求：

1. `idle`：弱显示，表明潜在网络
2. `running`：与当前 pipeline 阶段对应的连线增强
3. `completed`：保留结果态强度
4. `selected region`：与所选脑区关联的连接优先显示

### 7.5 波形带

波形带继续保留在主画布下缘，但从“可点击按钮阵列”改为“嵌入式监测带”。

要求：

1. 默认展示 4 到 8 条通道波形
2. 当前脑区关联通道自动高亮
3. 保留通道标签
4. 支持选中通道
5. 视觉上像监测仪器，而不是独立卡片容器

### 7.6 Pipeline 锚点

`source / filter / psd / band-power / ai-report` 不再以一排白卡节点存在，而是分布在脑主体周围的轨道锚点。

要求：

1. 锚点位置服务于读图顺序，而不是沿用旧的平面布局
2. 锚点状态通过环形、描边、脉冲和路径高亮表达
3. 点击锚点后，右上参数窗和右下 AI 助教必须同步切换

## 8. Interaction Model

### 8.1 3D 脑为第一交互入口

用户进入 `/lab` 后，最先操作的是中央脑主体，而不是文字区或模板列表。

### 8.2 Hover 规则

`hover` 脑区时，只出现轻量信息提示，内容限定为：

1. 脑区名
2. 当前活跃度
3. 对应频带或通道摘要

禁止 `hover` 时弹出大卡片遮挡主体。

### 8.3 Click 脑区联动

点击脑区后，必须至少联动三处：

1. 下缘波形带切换关联通道高亮
2. 右上参数/阶段窗显示对应解释或当前阶段关联信息
3. 右下 AI 助教切换到该脑区相关观察和教学说明

### 8.4 Click pipeline 锚点联动

点击任一 pipeline 锚点后：

1. 中央场景切换到对应的路径高亮和相关脑区强调
2. 右上窗切到对应参数或步骤说明
3. 右下 AI 助教切到该步骤说明

### 8.5 窗口行为规则

悬浮窗继续支持：

1. 展开
2. 收起
3. 轻拖动
4. 边缘吸附

但必须遵守：

1. 不遮挡中央脑主体的核心区域
2. 不支持自由重叠堆叠
3. 不做桌面窗口系统式管理

---

## 9. Visual Layer and Image Material Rules

### 9.1 三层边界必须严格

#### 科学层

只允许包含：

1. 标准脑 `mesh`
2. 区域分段
3. 连通性线束
4. 状态驱动热点
5. 受控相机视图

#### 仪器层

只允许包含：

1. 波形带
2. pipeline 锚点
3. 游标
4. 事件标记
5. 脑区标签
6. 测量辅助线

#### 视觉层

只允许包含：

1. 图片提炼的弱纹理
2. 局部说明图
3. 边缘注释片
4. AI/事件相关配图

### 9.2 图片素材允许的四种使用方式

1. `边缘悬浮标注层`：放在角部或边缘，像研究注释碎片
2. `局部信息放大片`：在选中脑区后显示相关教学图像
3. `背景弱纹理层`：从图片中提炼轮廓、颗粒或扫描感，低透明度铺在边缘背景
4. `AI/事件配图层`：进入右下 AI 助教或事件说明窗

### 9.3 图片素材禁止的使用方式

1. 不能把图片直接当脑表面主纹理
2. 不能让图片承担脑区拓扑职责
3. 不能用大图覆盖中央脑主体
4. 不能把页面做成拼贴海报

## 10. Data Mapping Model

### 10.1 数据来源

首版数据来源分为两类：

1. `标准科学资源`
   - 开源标准脑 `mesh`
   - 开源标准区域集合或 `atlas`
   - 开源可视化 `connectome scaffold`
2. `当前实验台状态`
   - `signal_preview`
   - `channel_power`
   - `events`
   - `pipeline_trace`
   - `node_explanations`

### 10.2 映射规则

当前实验数据不会直接变成几何结构，而是映射为受控视图模型：

1. `channel_power` -> 脑区热点强度
2. `events` -> 连线或脑区阶段性增强
3. `pipeline_trace` -> 外圈锚点状态与路径高亮
4. `signal_preview` -> 下缘波形带
5. `node_explanations` -> 右下 AI 助教内容

### 10.3 结构化视图模型要求

状态层需要新增一组与画布解耦的视图模型，至少包括：

1. `brainRegions`
2. `connectomeEdges`
3. `cameraPreset`
4. `waveChannels`
5. `pipelineAnchors`
6. `materialPanels`

其目的不是暴露原始 `NiiVue` API，而是让页面继续通过本地状态模型驱动可测试的 UI。

## 11. Window Responsibilities

四个悬浮窗的职责保持固定，不因引入 3D 脑而漂移：

1. 左上：实验选择
   - 轻量模板切换
   - 不承载说明长文
2. 右上：参数与阶段检查
   - 选中脑区或 pipeline 锚点时展示对应解释
3. 左下：读数与波形
   - 指标、波形、局部监测数据
4. 右下：AI 助教与事件
   - 教学解释、观察结论、事件时间点、素材配图

原则：窗口是实验配套组件，不是主视觉容器。

## 12. Error Handling and Degradation

首版必须具备明确降级策略，不能让页面因为 `WebGL` 或资源问题直接失效。

### 12.1 NiiVue 加载失败

回退为：

1. 静态占位脑视图
2. 保留波形带
3. 保留四窗与 AI 说明
4. 显示轻量错误提示

### 12.2 标准脑资源缺失

回退为简化脑区视图，不阻断实验选择、参数调整和运行流程。

### 12.3 实验数据为空

保留可交互脑主体，但热点和连线进入待机态，AI 窗显示“等待运行”态。

### 12.4 性能不足

优先降级：

1. 弱背景纹理
2. 边缘辉光
3. 非关键扫描效果

禁止降级：

1. 核心脑主体交互
2. 脑区选择联动
3. 波形和参数联动

---

## 13. Scope Boundaries

### 13.1 首版明确要做

1. `NiiVue` 驱动的可旋转/缩放/复位标准脑主视图
2. 脑区热点高亮
3. connectome 连线强弱变化
4. 脑区点击联动波形、参数窗、AI 助教
5. pipeline 锚点与脑主体联动
6. 图片素材作为边缘注释、弱背景纹理或 AI 配图进入系统

### 13.2 首版明确不做

1. 用户上传 `NIfTI / atlas / mesh`
2. 完整医学阅片工作站
3. 自由编辑脑区和连线
4. 多脑模板切换
5. 真实设备实时采流
6. 从图片反推脑区结构

---

## 14. Testing Strategy

本次设计需要覆盖三类验证：

### 14.1 状态模型测试

验证新的画布视图模型是否正确映射：

1. 脑区热点强度
2. 连线强度
3. 选中脑区联动状态
4. pipeline 锚点状态

### 14.2 组件测试

验证主画布容器是否正确：

1. 渲染 `NiiVue` 容器和降级占位
2. 响应脑区选择事件
3. 响应 pipeline 锚点选择事件
4. 与现有悬浮窗联动

### 14.3 浏览器验证

验证真实页面是否达到体验目标：

1. 首屏无纵向滚动
2. 中央脑主体非空白
3. 脑区点击能联动三处以上信息区
4. 悬浮窗不遮挡中央主体
5. 降级路径在资源缺失或失败时仍可用

---

## 15. Acceptance Criteria

本次子项目完成后，必须满足以下结果：

1. 用户第一眼看到的是研究型脑实验主视图，而不是卡片工作台。
2. 中央脑主体基于成熟开源科学组件，而不是装饰性 3D 模型。
3. 主画布支持轻交互研究视角，且交互范围受控。
4. 点击脑区能稳定联动至少三处信息区。
5. 现有实验数据能驱动热点、连线、波形与 AI 助教的一致变化。
6. 用户图片素材进入系统后能提升完成度，但不会覆盖或替代科学层。
7. 在 `NiiVue` 或资源失败时，实验台仍保留可用的教学工作流。
