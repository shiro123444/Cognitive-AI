# EDUFISH NeuroLab 教学实验台重设计

> Date: 2026-05-11
> Scope: 将 `/lab` 从“页面式卡片工作台”重设计为“单屏教学实验驾驶舱”
> Status: approved for planning

---

## 1. Goal

当前 `/lab` 已经具备实验模板、固定 EEG pipeline、参数编辑、仪器图表和 AI 报告，但整体视觉仍然像“标题 + 三栏 + 底部 tab”的页面式后台。用户能完成操作，但感受到的是组件排布，不是实验正在发生。

本次重设计的目标不是扩展实验协议，而是把现有能力重新组织成一个真正的教学实验台：

1. 首屏看起来像脑机实验驾驶舱，而不是文字卡片页。
2. 主体是全景实验画布，信号和实验过程优先于说明文案。
3. 数据、参数、AI 解释改为悬浮实验组件，而不是大块面板。
4. 沿用现有 EDUFISH 的克莱因蓝与黑白灰视觉体系，不重新定义配色。
5. 在保留现有后端接口和实验状态模型的前提下，优先重构前端表现层。

---

## 2. Context Findings

### 2.1 当前能力已经足够支撑实验台

现有后端和状态层已经能提供：

1. 固定 pipeline：`source -> filter -> psd -> band-power -> ai-report`
2. 节点级参数：采样率、时长、通道数、滤波上下限
3. artifact 数据：
   - `signal_preview`
   - `psd`
   - `channel_power`
   - `events`
   - `pipeline_trace`
4. AI 报告数据：
   - `observations`
   - `limitations`
   - `next_steps`
   - `node_explanations`

结论：问题不是数据不够，而是这些数据都被装进同一种“面板/卡片”语法里。

### 2.2 当前 UI 的核心问题

当前界面的结构是：

1. 顶部页头说明
2. 左侧模板列表
3. 中央 pipeline 画布
4. 右侧 inspector
5. 底部 instruments tab

这套结构的主要问题：

1. `LabView.vue` 仍然是典型三栏页面，首屏阅读顺序先落在标题文案，而不是实验本体。
2. `NeuroLabCanvas.vue` 只是直线节点图，空间利用率低，缺乏实验场感。
3. `NeuroLabInspector.vue` 是通用表单面板，看起来像后台配置页。
4. `NeuroLabInstruments.vue` 依赖 tab 切换，图表都被收纳进同一种白底内容区。
5. 视觉层级过于平均，所有区块都像同等重要的卡片。

---

## 3. User Constraints Confirmed

本轮设计经过确认后的约束如下：

1. 产品定位：`教学实验台`
2. 首屏重点：`信号优先`
3. 主画布类型：`脑区拓扑 + 多通道波形的混合主控台`
4. 辅助组件交互：`半自由停靠`
5. 页面结构：`单屏驾驶舱`
6. 视觉系统：保持当前 `Klein Blue + 黑白灰`
7. 风格要求：加入明显的 `不对称艺术感`

---

## 4. Approaches Considered

### 4.1 Approach A: 继续优化现有三栏页

在现有结构上加强样式、图表和文案。

优点：

1. 改动最小
2. 测试影响最小
3. 风险低

缺点：

1. 仍然会像“卡片后台”
2. 无法建立实验驾驶舱的首屏气质
3. 波形和脑区图只能继续附属在面板里

### 4.2 Approach B: 示教型脑机实验台

重构为单屏全景实验画布，四周围绕薄型悬浮实验窗。

优点：

1. 最符合“不是一堆文字卡片”的目标
2. 能同时表达脑区、波形、pipeline、AI 解释
3. 兼顾教学可读性与实验专业感
4. 最大程度复用现有数据和接口

缺点：

1. 前端布局与交互层需要整体重组
2. 需要建立新的信息层级和动画语言

### 4.3 Approach C: 波形墙控制台

以多通道 EEG 波形墙为绝对主角，脑区图与流程退居辅助。

优点：

1. 专业感最强
2. 实验测量感最直接

缺点：

1. 教学友好度一般
2. 如果当前数据仍以 synthetic 为主，首屏会显得“硬但不满”

### 4.4 Recommendation

采用 **Approach B: 示教型脑机实验台**。

原因：

1. 它最适合当前的教学场景。
2. 它不要求先更换后端实验协议，就能显著提升平台质感。
3. 它允许后续继续接入更成熟的外部实验组件，而不会推翻本次 UI 骨架。

## 5. Design Principles

### 5.1 用实验场语法替换页面语法

界面要让用户先看到“实验正在发生”，而不是先看到“这里有几个模块”。

### 5.2 图形优先于说明

同一份信息优先以波形、脑区热点、状态灯、刻度、迷你图、路径高亮表达，文本只保留结论句。

### 5.3 组件悬浮但不失控

悬浮组件必须支持拖动、展开、收起，但移动范围和吸附区受控，避免把教学实验台拖成桌面窗口系统。

### 5.4 不对称但可读

构图可以不均衡，但读图顺序必须明确：主画布第一，悬浮控制第二，说明文字最后。

### 5.5 不重新造视觉系统

继续使用现有 token、字体、边框风格、克莱因蓝主色，不单独发明一套“脑机平台品牌色”。

---

## 6. Page Architecture

`/lab` 重构为单屏驾驶舱，按以下层级组织：

1. 顶部薄控制带
2. 中央全景实验画布
3. 四角悬浮实验窗
4. 轻量状态与提示层

### 6.1 顶部薄控制带

顶部不再使用大标题和长摘要，只保留：

1. 当前实验名称
2. 实验模式标签
3. 当前运行状态
4. `Run Pipeline` 主按钮
5. 可选的时间、会话或实验编号信息

目标是压缩叙事性页头，把首屏视觉重点让给实验本体。

### 6.2 中央全景实验画布

主画布占首屏约 70% 视觉权重，成为绝对中心。

画布的读图顺序应为：

`脑区主图 -> 波形动态 -> pipeline 执行路径 -> 悬浮读数 -> AI 观察`

### 6.3 四角悬浮实验窗

四个悬浮窗围绕主画布分布，形成不对称构图，但保持阅读秩序。

### 6.4 页面滚动策略

首版按单屏驾驶舱设计，核心体验尽量不依赖纵向滚动。若需要放置二级详情，使用抽屉、展开层或局部放大，不延长页面。

---

## 7. Main Canvas Design

主画布不是单一图表，而是一个五层叠加的实验场。

### 7.1 基础坐标层

包含：

1. 细网格
2. 时间刻度弱提示
3. 通道编号和测量辅助线

作用：

1. 提供测量感
2. 给动态信号提供秩序基底
3. 增强实验设备语义，而非装饰

### 7.2 波形底层

多通道 EEG 波形作为主画布底层持续存在。

要求：

1. 默认展示 4 到 8 通道
2. 每条波形带明确通道标识
3. 支持选中通道高亮
4. 运行态下有扫描线与振幅感
5. 波形直接嵌入画布，不使用独立大面板包裹

### 7.3 脑区拓扑主层

画布中央使用教学可读型脑区拓扑，而不是写实医学插图。

要求：

1. 脑区节点和连线具备激活态
2. 能响应频带、事件阶段和当前选中通道
3. 通过热点、脉冲圈、局部能量轮廓表达活跃区域
4. 与波形和参数窗形成联动关系

### 7.4 Pipeline 路径层

`source -> filter -> psd -> band-power -> ai-report` 继续存在，但不再作为直线节点图单独展示。

要求：

1. 节点变成主画布中的锚点
2. 路径可沿边缘或穿过主画布组织
3. 运行时出现流向高亮、节点脉冲和完成标记
4. 状态表达优先靠图形和路径，不靠文字列表

### 7.5 前景交互层

用于承接精细交互：

1. hover 脑区显示轻量摘要
2. hover 波形显示测量游标
3. hover 节点显示当前阶段提示
4. 点击后将详细信息送入悬浮窗，而不是在主画布堆长文

---

## 8. Floating Instrument Windows

悬浮组件统一改为薄型实验窗，而不是通用内容卡片。

### 8.1 Interaction Rules

统一规则：

1. 默认小体积常驻
2. 可展开、收起、拖动
3. 拖动时只允许在预设区域吸附
4. 内容以图形化读数为主
5. 大小分级明确，避免四窗平均

### 8.2 左上：实验选择窗

职责：

1. 显示当前实验
2. 提供实验模板切换
3. 展示实验目标或模式标签

改造原则：

1. 模板列表从大按钮列改成轻量实验索引
2. 不占据视觉中心
3. 保持切换效率

### 8.3 右上：参数控制窗

职责：

1. 承接当前节点参数编辑
2. 显示节点简短说明
3. 显示当前节点状态

改造原则：

1. 从表单盒子改成仪器参数板
2. 采样率优先使用分段选择
3. 数值参数使用紧凑输入或 stepper
4. 节点解释压缩为短句式提示，不放长段落

### 8.4 左下：实时指标窗

职责：

1. 显示采样率、通道数、时长、阶段状态、事件数
2. 提供运行中的实时读数区

改造原则：

1. 使用状态灯、编号、迷你 sparkline、条带读数
2. 强调“实验正在运行”
3. 成为仪器感的关键支点

### 8.5 右下：AI 助教窗

职责：

1. 输出当前观察
2. 输出可能含义
3. 输出下一步建议

改造原则：

1. 不再默认展示长报告
2. 以短句式实验旁白为主
3. 详细报告进入二级展开态

---

## 9. Motion and Interaction Language

本次不追求装饰动画，而是建立“仪器交互语法”。

### 9.1 常驻动态

1. 波形持续轻微扫描
2. 脑区热点低频脉冲
3. pipeline 路径出现轻量流动高亮
4. 运行状态读数持续刷新

### 9.2 鼠标交互

主画布上采用三类轻交互：

1. `局部聚焦`
   - 鼠标靠近脑区或波形时，目标区域提亮，外围轻微退后
2. `测量游标`
   - 波形上出现细准星、竖线或读数提示
3. `联动映射`
   - hover 通道时，对应脑区亮起
   - hover 脑区时，对应波形、频带或节点状态提示同步高亮

### 9.3 悬浮窗动态

1. hover 时边框、标题和状态条增强
2. 展开时以仪器抽屉式过渡呈现
3. 拖动时显示吸附轨迹与定位线

### 9.4 运行流程反馈

点击 `Run Pipeline` 后应有明显过程反馈：

1. 控制带进入运行态
2. pipeline 节点按顺序点亮
3. 波形先进入采集中状态
4. PSD、频带与事件信息随后依次就绪
5. AI 助教窗最后更新观察结果

## 10. Component Mapping

本次以“保留数据层、重做表现层”为原则。

### 10.1 保留的部分

保留：

1. 后端实验运行接口
2. `neuroLabPipelineState.js` 状态模型与数据映射逻辑
3. 实验模板与固定 pipeline
4. `signal_preview / psd / channel_power / events / node_explanations` 数据契约

### 10.2 需要重做的部分

#### `frontend/src/views/LabView.vue`

从页头 + 三栏 + 底部 tab 改为：

1. 顶部薄控制带
2. 中央单屏主画布
3. 四角悬浮窗编排层

#### `frontend/src/components/NeuroLabCanvas.vue`

从直线 `VueFlow` 展示改为：

1. 全景脑区拓扑
2. 多通道波形底层
3. pipeline 路径锚点
4. hover 联动层

注：首版仍可继续借用 `VueFlow` 的节点和连接数据能力，但最终视觉不应再直接暴露为标准流程图库默认外观。

#### `frontend/src/components/NeuroLabInspector.vue`

从通用表单板改为：

1. 仪器参数窗
2. 当前节点状态摘要
3. 短句式实验提示

#### `frontend/src/components/NeuroLabInstruments.vue`

从 tab 容器拆分为：

1. 实时指标窗
2. AI 助教窗
3. 可按需展开的图谱窗或二级细节层

## 11. Data Visualization Precision Requirements

第一阶段必须显著提升以下几点：

1. 波形不再只突出单通道，至少支持 4 到 8 通道同时可读。
2. 每条波形必须有清晰通道标识和时间秩序。
3. 事件信息不能只存在于表格里，必须与时间位置建立可视关联。
4. 频谱和频带结果必须与主画布或当前焦点联动，避免成为孤立图表。
5. AI 助教解释要围绕当前选中脑区、通道或节点输出，减少泛泛报告感。

---

## 12. Phase 1 Delivery Boundary

首个实现阶段只处理前端实验台重构，不扩展实验协议。

### 12.1 In Scope

1. 新的单屏工作台布局
2. 新的主画布视觉结构
3. 悬浮实验窗交互
4. 运行状态动态反馈
5. 波形、脑区、pipeline、AI 解释的联动体验

### 12.2 Out of Scope

1. 新增真实硬件采集协议
2. 接入完整外部桌面 BCI 系统
3. 扩展新的实验模板类型
4. 更改后端 artifact schema 的大范围设计

---

## 13. Testing Strategy

实现阶段需要覆盖以下验证：

1. 状态层测试
   - 节点选择、参数变更、运行状态映射仍然正确
2. 组件测试
   - 主画布层级渲染
   - 悬浮窗展开/收起/吸附逻辑
   - hover 与选中联动行为
3. 浏览器验证
   - 单屏首屏是否无需滚动即可完成核心操作
   - 运行流程反馈是否按阶段出现
   - 主画布与悬浮窗在桌面视口下是否保持稳定
4. 回归验证
   - `/lab` 登录访问、实验运行、报告展示和进度记录仍然正常

---

## 14. Risks and Mitigations

### 14.1 风险：悬浮窗太多，重新变成漂浮卡片

缓解：

1. 控制数量为四个主窗
2. 做出大小主次
3. 默认只展示核心读数

### 14.2 风险：动态太多，界面显得廉价或嘈杂

缓解：

1. 背景层动画弱
2. 核心数据层清晰稳定
3. hover 反馈短促精确
4. 减少闪烁和大范围跳动

### 14.3 风险：主画布过于追求视觉，牺牲参数可用性

缓解：

1. 参数输入统一进入右上控制窗
2. 保留结构化表单输入，但换成仪器式外观
3. 确保键盘和鼠标都能完成关键操作

---

## 15. Design Summary

这次重设计的核心不是增加更多组件，而是把现有实验能力重新翻译成教学实验台的语言：

1. 页面式布局改为单屏驾驶舱
2. 卡片式模块改为全景实验画布 + 悬浮实验窗
3. 文本说明主导改为波形、脑区、路径和状态主导
4. 静态展示改为有节奏的实验过程反馈
5. 继续沿用现有克莱因蓝视觉系统，并通过不对称构图建立更强的艺术感和识别度

这份设计明确优先级：先把实验台气质和交互语法做对，再考虑接入更多外部实验组件和真实数据源。
